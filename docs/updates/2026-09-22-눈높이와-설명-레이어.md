# 2026-09-22 — 눈높이와 설명 레이어 (v1.2.0)

ELI5 스킬([DreambigOu/ELI5](https://github.com/DreambigOu/ELI5), MIT)을 study-on-canvas 에 접목해 노트가 다루는 축을 하나 늘렸다.

## 접목 배경

study-on-canvas 가 지금까지 관리한 것은 무엇을 다룰지였다. 후속 개념을 사이드바에 쌓고, 개념 지도로 상·하위 관계를 그리고, 다룬 것과 안 다룬 것을 색으로 구분한다. 전부 탐색의 축이다.

정작 설명을 어느 깊이로 쓸지는 규정한 적이 없었다. SKILL.md 가 말하는 기준은 분량 하나뿐이었다. "한 화면 분량", "스크롤 1~2 화면". 그래서 같은 노트 안에서도 패널마다 설명 수준이 들쑥날쑥했다.

ELI5 는 정확히 그 반대편 축만 다루는 스킬이다. 무엇을 설명할지에는 관심이 없고, 누구에게 설명할지에 따라 어휘·비유·프레이밍을 어떻게 바꿀지만 표로 정리해 둔다. 두 축이 직교하니 한쪽 표를 다른 쪽 빈칸에 그대로 끼워 넣을 수 있었다.

## 변경 사항

ELI5 의 `SKILL.md` 는 크게 네 덩어리다. 대상 분류표(Step 1), 설명 구조(Step 3 Structure), 언어 보정(Language Calibration), 지켜야 할 선(Important Reminders). 아래 변경은 이 넷을 각각 다른 자리에 끼워 넣은 결과이고, 항목마다 무엇이 바뀌었는지와 원본의 어느 대목에서 왔는지를 함께 적는다.

### 1. 세션 눈높이 — 대상 분류표와 언어 보정의 압축

세션을 열 때 저장 경로와 함께 눈높이를 묻는다. 입문 · 인접 · 실무 셋 중 하나이고, 한 번 정하면 세션 내내 바꾸지 않는다. 노트 헤더에 배지로 박힌다. 이 값이 설명문의 기본 수준을 정하고 사이드바에 쌓을 후속 개념의 성격까지 바꾼다.

ELI5 는 대상을 네 분류군(Ages · Grade Levels · Job Roles · Relationships)으로 나누고 요청이 들어올 때마다 파싱한다("Parse the user's request to determine who the explanation is for"). 학습 노트는 독자가 사용자 한 명이라 관계·나이 축이 필요 없다. 그래서 네 분류군 대신 "이 분야를 얼마나 아는가" 한 축으로 접고, 단계 수는 Language Calibration 이 실제로 나눈 세 묶음(simple / technical / business)에 맞춰 셋으로 뒀다.

각 단계의 작성 기준은 그 묶음의 지침을 거의 그대로 옮겼다.

| 눈높이 | 대응하는 ELI5 지침 |
| --- | --- |
| 입문 | simple audiences — "No jargon. Zero. If a technical term is essential, define it immediately." / "One idea per sentence." / "Concrete over abstract." |
| 실무 | technical audiences — "Use proper terminology — they'll feel patronized without it." / "Focus on the *interesting* parts: trade-offs, edge cases, design decisions." / "Be concise — respect their existing knowledge." |
| 인접 | 직접 대응이 없다. Job Roles 의 엔지니어 행에 있는 대조 전략(`Compare to things they already know: "It's like a hash map but with X difference."`)을 중간 단계로 승격해 신설했다. |

바꾼 것도 둘 있다. ELI5 는 대상이 불분명하면 다섯 살로 떨어진다(`If the audience isn't explicitly stated, default to "Age 5" (classic ELI5).`). 캔버스의 기본값은 인접이다. 일회성 설명은 쉬운 쪽으로 틀리는 편이 안전하지만, 노트는 한 권 내내 과하게 쉬우면 다시 읽을 이유가 없어진다. 그리고 ELI5 가 요청마다 대상을 다시 파싱하는 것과 달리 눈높이는 세션에 한 번 고정한다. 패널마다 수준이 흔들리면 노트로 안 읽힌다.

### 2. 설명 레이어 — 80% 정확도 원칙과 분량 지침의 분해

패널 하나가 쉽게 · 기본 · 깊게 세 층을 담을 수 있게 됐다. 개념을 처음 다룰 때는 기본 레이어만 채운다. 레이어가 하나뿐이면 전환 버튼은 저절로 숨으므로, 쓰지 않으면 화면에 흔적이 남지 않는다.

쉽게 레이어에 붙은 "정확도를 80% 까지 깎아도 된다"는 Important Reminders 의 한 줄을 그대로 받은 것이다.

> Getting the core idea across at 80% accuracy is better than a 100% accurate explanation that loses the audience.

레이어별 분량(3문장 이내 / 스크롤 1~2 화면 / 필요한 만큼)은 "Match the length to the audience: short and sweet for young kids, more detailed for technical audiences who want depth" 를 세 칸으로 끊었다. 세 층의 역할 분담은 Structure 4단계(what → analogy → details → so what)를 분해한 결과다. analogy 가 쉽게로, details 가 기본으로 갔고, Grade Levels 의 대학원 행에 있는 "nuance, trade-offs, edge cases, and deeper implications" 가 깊게가 됐다.

여기에 원본에 없는 것을 하나 더했다. ELI5 는 한 번에 한 대상, 한 설명이다. 캔버스는 두 버전을 같은 패널에 동시에 남긴다. 쉬운 버전과 정확한 버전을 번갈아 보면 어디를 단순화했는지가 드러나고, 그 간극이 곧 아직 이해하지 못한 지점이다. 설명이 끝나면 사라지는 도구에는 필요 없던 장치다.

### 3. 더 쉽게 경로 — 트리거 흡수와 출력 형태 교체

기존 스킬에는 이해 실패를 다루는 경로가 없었다. 사이클이 개념 설명 → HTML 기록에서 끝나니, 못 알아들으면 하위 개념으로 더 내려가는 수밖에 없었다. 아래로 파는 것과 옆에서 다시 말하는 것은 다른 동작인데 후자가 빠져 있었다.

ELI5 가 발동 조건에 적어 둔 표현들은 전부 이해 실패 신호다. "dumb it down", "simplify this for", "explain like I am". ELI5 는 이걸 1급 입력으로 다룬다. 캔버스에는 그 입력을 받는 자리 자체가 없었다. 그래서 트리거는 그대로 흡수하고 출력 형태만 바꿨다. ELI5 는 새 답변을 내놓고, 캔버스는 현재 패널에 쉽게 레이어를 붙인다.

이제 "잘 모르겠어", "더 쉽게" 는 새 개념 사이클이 아니라 현재 패널에 쉽게 레이어를 붙이는 동작이다. 탭도 카드도 늘어나지 않는다. 이해를 돕자고 사이드바를 불리면 압도되는 것만 늘기 때문이다.

반대 방향도 같다. "왜 그런지", "예외는 없는지" 에는 깊게 레이어가 붙는다. 다만 답이 스크롤 한 화면을 넘기면 그때는 독립된 개념으로 분리한다.

`audience-calibration.md` 의 "누구에게도 내려다보며 말하지 않는다. 쉬운 설명은 유치한 설명이 아니다" 도 같은 절에서 왔다.

> Never talk down to anyone. A 5-year-old explanation should feel delightful, not dumbing-down.

### 4. teach-back 요약 탭 — Job Roles 표의 용도 전환

대상을 정해 요약을 요청하면 노트 맨 끝에 요약 탭이 생긴다. 매니저면 결정과 리스크로, 디자이너면 사용자 경험으로 프레이밍이 기운다. 이 규칙이 곧 Job Roles 표의 두 행이다.

| 대상 | ELI5 Job Roles 표의 해당 행 |
| --- | --- |
| Manager | 관심사 "Impact, timeline, risk, cost" / 프레이밍 "Business outcomes, team implications, what decisions need to be made" |
| Designer | 관심사 "User experience, visual impact, flow" / 프레이밍 "How it affects the user, interaction patterns, accessibility" |

business audiences 지침의 "Lead with impact and outcomes", "Frame in terms of decisions: This means we should..." 도 요약 탭의 서술 방식에 그대로 들어갔다.

용도는 뒤집었다. ELI5 에서 대상 전환은 설명의 목적지다. 캔버스에서는 teach-back — 배운 것을 남에게 설명해보며 이해를 점검하는 학습법 — 의 도구이고, 결과가 노트에 산출물로 남는다. 그래서 요약 탭은 개념이 아니라 산출물로 취급해 사이드바 카드를 만들지 않고 `data-parent` 도 쓰지 않는다. 개념 지도에 섞이면 안 되기 때문이다.

### 5. 비유 영역 표 — Ages Style 열과 Job Roles 열의 병합

`audience-calibration.md` 3절의 비유 소재 표는 ELI5 의 두 표에서 비유 부분만 뽑아 합쳤다. 어린이 행의 장난감·동물·놀이터는 Age 5 의 "toys, animals, candy, playground" 에서, 매니저 행의 비즈니스 성과·리스크는 Manager 행의 "Business outcomes" 에서 왔다. 10대 행에 "억지 유행어는 쓰지 않는다" 를 남긴 것도 원본이 그 자리에 적어 둔 경고 때문이다.

> Teenagers: Slightly casual but not cringey. No "fellow kids" energy.

### 6. 슬래시 명령 전용 전환 — 트리거 충돌 회피

v1.1.0 에서 열어 둔 자연어 호출("캔버스로 대화하자")을 거둬들였다.

설명·요약 계열 스킬은 트리거가 넓다. ELI5 만 해도 "explain this to", "simplify this for", "dumb it down" 을 다 잡는다. 두 스킬을 나란히 두고 자연어 호출도 열어 두면, 캔버스 세션 도중 "쉽게 설명해줘" 한마디에 다른 스킬이 끼어든다. 터미널에만 답하고 HTML 을 갱신하지 않는 사이클이 생긴다.

노트가 대화에 뒤처지는 순간 이 플러그인은 쓸모를 잃는다. 그래서 진입점을 `/study-on-canvas` 하나로 좁혔다. 세션이 열려 있는 동안에는 사용자가 어떤 표현을 쓰든 기록 사이클을 유지하도록 SKILL.md 에 못을 박았다.

표를 흡수하는 쪽을 택한 것도 같은 이유다. ELI5 를 별도 스킬로 설치해 두고 부르는 대신, 대상별 분류표를 `references/audience-calibration.md` 로 옮겨 왔다. 트리거가 겹칠 여지가 없고 배포도 플러그인 하나로 끝난다.

### 미채택 항목

- Relationships 분류군(배우자 · 부모 · 친구)과 Ages 의 세분화. 노트의 독자는 사용자 본인 하나다. 다만 teach-back 대상은 될 수 있어 비유 영역 표에만 어린이 · 10대 · 일반 성인 행을 남겼다.
- Tone Matching 절. 열정적으로, 캐주얼하게 같은 지침은 말로 설명할 때의 것이다. 노트는 문어체로 쌓이는 기록이라 맞지 않는다.
- Step 2 (Read the Source Material). 캔버스는 진행 중인 대화 자체가 원천이라 설명 전에 읽을 자료를 따로 찾는 단계가 필요 없다.

### 두 축의 교차점 — 후속 개념 선정

`audience-calibration.md` 5절 — 눈높이에 따라 사이드바에 쌓을 후속 개념의 성격이 달라진다는 규칙 — 은 ELI5 에 대응하는 내용이 없다. 두 스킬의 축이 직교한다고 말했지만, 교차점이 하나 생겼다. ELI5 가 관리하던 "어떻게 설명할지" 가 캔버스가 관리하는 "무엇을 다룰지" 를 고르는 기준으로 쓰인다. 입문이면 비유를 지탱하는 하위 개념을, 실무면 trade-off 가 갈리는 분기점을 고른다.

## 기존 노트 호환성

영향 없다. 생성된 노트는 CSS·JS 를 자기 안에 들고 있는 단일 파일이라, 이전 버전으로 만든 노트는 이전 동작 그대로 열린다.

새 템플릿도 레이어가 없는 패널을 그냥 통과시킨다. 판정은 `.explanation` 안에 `.layer` 가 있는지 하나로 끝난다. 없으면 전환 UI 를 세우지 않고 내용을 그대로 보여준다.
