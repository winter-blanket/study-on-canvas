# 2026-09-22 — 눈높이와 설명 레이어 (v1.2.0)

ELI5 스킬([dreambigou/eli5](https://github.com/dreambigou/eli5), MIT)을 study-on-canvas 에 접목해 노트가 다루는 축을 하나 늘렸다.

## 왜 접목했나

study-on-canvas 가 지금까지 관리한 것은 무엇을 다룰지였다. 후속 개념을 사이드바에 쌓고, 개념 지도로 상·하위 관계를 그리고, 다룬 것과 안 다룬 것을 색으로 구분한다. 전부 탐색의 축이다.

정작 설명을 어느 깊이로 쓸지는 규정한 적이 없었다. SKILL.md 가 말하는 기준은 분량 하나뿐이었다. "한 화면 분량", "스크롤 1~2 화면". 그래서 같은 노트 안에서도 패널마다 설명 수준이 들쑥날쑥했다.

ELI5 는 정확히 그 반대편 축만 다루는 스킬이다. 무엇을 설명할지에는 관심이 없고, 누구에게 설명할지에 따라 어휘·비유·프레이밍을 어떻게 바꿀지만 표로 정리해 둔다. 두 축이 직교하니 한쪽 표를 다른 쪽 빈칸에 그대로 끼워 넣을 수 있었다.

## 무엇이 바뀌었나

### 1. 세션 눈높이

세션을 열 때 저장 경로와 함께 눈높이를 묻는다. 입문 · 인접 · 실무 셋 중 하나이고, 한 번 정하면 세션 내내 바꾸지 않는다. 노트 헤더에 배지로 박힌다.

이 값이 설명문의 기본 수준을 정하고 사이드바에 쌓을 후속 개념의 성격까지 바꾼다. 입문이면 방금 쓴 비유를 지탱하는 하위 개념을, 실무면 trade-off 가 갈리는 분기점을 고른다.

### 2. 설명 레이어

패널 하나가 쉽게 · 기본 · 깊게 세 층을 담을 수 있게 됐다. 개념을 처음 다룰 때는 기본 레이어만 채운다. 레이어가 하나뿐이면 전환 버튼은 저절로 숨으므로, 쓰지 않으면 화면에 흔적이 남지 않는다.

가치는 두 레이어가 나란히 놓였을 때 나온다. 쉬운 버전과 정확한 버전을 번갈아 보면 어디를 단순화했는지가 드러나고, 그 간극이 곧 아직 이해하지 못한 지점이다.

### 3. 더 쉽게 — 이해가 막혔을 때의 경로

기존 스킬에는 이해 실패를 다루는 경로가 없었다. 사이클이 개념 설명 → HTML 기록에서 끝나니, 못 알아들으면 하위 개념으로 더 내려가는 수밖에 없었다. 아래로 파는 것과 옆에서 다시 말하는 것은 다른 동작인데 후자가 빠져 있었다.

이제 "잘 모르겠어", "더 쉽게" 는 새 개념 사이클이 아니라 현재 패널에 쉽게 레이어를 붙이는 동작이다. 탭도 카드도 늘어나지 않는다. 이해를 돕자고 사이드바를 불리면 압도되는 것만 늘기 때문이다.

반대 방향도 같다. "왜 그런지", "예외는 없는지" 에는 깊게 레이어가 붙는다. 다만 답이 스크롤 한 화면을 넘기면 그때는 독립된 개념으로 분리한다.

### 4. Teach-back 요약 탭

대상을 정해 요약을 요청하면 노트 맨 끝에 요약 탭이 생긴다. 매니저면 결정과 리스크로, 디자이너면 사용자 경험으로 프레이밍이 기운다.

요약 탭은 개념이 아니라 산출물이라 사이드바 카드를 만들지 않고 `data-parent` 도 쓰지 않는다. 개념 지도에 섞이면 안 되기 때문이다.

### 5. 슬래시 명령 전용으로 전환

v1.1.0 에서 열어 둔 자연어 호출("캔버스로 대화하자")을 거둬들였다.

설명·요약 계열 스킬은 트리거가 넓다. ELI5 만 해도 "explain this to", "simplify this for", "dumb it down" 을 다 잡는다. 두 스킬을 나란히 두고 자연어 호출도 열어 두면, 캔버스 세션 도중 "쉽게 설명해줘" 한마디에 다른 스킬이 끼어든다. 터미널에만 답하고 HTML 을 갱신하지 않는 사이클이 생긴다.

노트가 대화에 뒤처지는 순간 이 플러그인은 쓸모를 잃는다. 그래서 진입점을 `/study-on-canvas` 하나로 좁혔다. 세션이 열려 있는 동안에는 사용자가 어떤 표현을 쓰든 기록 사이클을 유지하도록 SKILL.md 에 못을 박았다.

표를 흡수하는 쪽을 택한 것도 같은 이유다. ELI5 를 별도 스킬로 설치해 두고 부르는 대신, 대상별 분류표를 `references/audience-calibration.md` 로 옮겨 왔다. 트리거가 겹칠 여지가 없고 배포도 플러그인 하나로 끝난다.

## 기존 노트는 어떻게 되나

영향 없다. 생성된 노트는 CSS·JS 를 자기 안에 들고 있는 단일 파일이라, 이전 버전으로 만든 노트는 이전 동작 그대로 열린다.

새 템플릿도 레이어가 없는 패널을 그냥 통과시킨다. 판정은 `.explanation` 안에 `.layer` 가 있는지 하나로 끝난다. 없으면 전환 UI 를 세우지 않고 내용을 그대로 보여준다.
